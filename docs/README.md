## Arbeitsplanung

Neue Features, Bugs, Verbesserungen und offene Aufgaben werden in [GitHub Issues](https://github.com/martinderm/austrian-law-kit/issues) geführt. Keine parallelen Backlogs, Next-Session-Dateien oder laufenden Statuschroniken in docs/. Issues enthalten Ziel, Scope und Abnahmekriterien; abgeschlossene Änderungen stehen im CHANGELOG. Archivierte Aufgaben sind keine Zusage einer Implementierung.

Architektonische, strukturelle, prozessuale und schematische Änderungen müssen die betroffenen Karten in docs/system-map/ im selben Änderungssatz aktualisieren. Die Map beschreibt den belegten Istzustand; Code und fachliche Verträge bleiben maßgeblich.
